# GridSense One Studio — developer kit

_Generated by `plan/package_devkit.py` on 2026-10-14T14:32:21+00:00 from `one-studio/app`. Do not edit by hand: regenerate (below)._

The One Studio ISO-NE interconnection screening app, running on **recorded API responses** instead of the 3 GB
DuckDB. The UI code is identical to the DB-backed app; only the data source differs.

## Run

```
cd app
python server.py --port 8106 --fixtures fixtures
```
Then open <http://127.0.0.1:8106/analytics-analyzer-studio.html> in Chrome and pick a project from the project menu.

**Requirements:** Python 3.11+ (standard library only: fixtures mode never imports DuckDB) and Google Chrome.
Node.js 20+ and Playwright are needed only to run the browser tests or to re-record fixtures.

`/health` reports `"mode": "fixtures"` and the fixture set id. Any API path outside the set answers
`404 {"error": "not in the dev-kit fixture set", "path": ...}`.

## Regenerate the fixtures

Needs the unified DuckDB, the `duckdb` Python package, Node.js and the pinned Playwright in `one-studio/testenv`.
Run from the main app (`one-studio/app`), never from this copy:

```
python plan/export_fixtures.py --out <dir>                 # starts its own --db server on an ephemeral port
python plan/package_devkit.py --fixtures <dir>             # rebuilds this folder
node tests/fixture-parity.mjs --fixtures <this folder>/fixtures   # every recorded path equals the --db server
```
`export_fixtures.py` walks every stage × the 5 projects × their option buses (+ the test pins and the hub) in headless
Chrome, captures each `/api/*` request, completes each bus-keyed endpoint for every bus in the set, and stores the
responses. It also opens the LMP Continuum tab at each of those buses and clicks every workflow screen, so it needs the
Continuum service (127.0.0.1:5034) running; it only GETs from it, through the app's proxy.
